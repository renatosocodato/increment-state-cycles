# Increment State Cycles

This research package accompanies the manuscript “Increment-state cycles do not determine physical reversibility”. It contains the mathematical calculations, saved synthetic simulation summaries and individual-study outputs, and R source for the five main figures. The article reproduction data are generated by the models in this package. A separate applied example contains group-level summaries only. A prospective microglial application in the manuscript is not experimental validation of the synthetic models. The separate range-theory project is not part of this package.

## Install and analyse trajectories

```sh
python -m pip install .
increment-state-cycles examples/synthetic_trajectories.csv
```

```python
from increment_state_cycles import contrasts, physical_reverse

physical_reverse("PRE")  # 'REP'
result = contrasts(["EPRERP", "PRERPE"])
```

Provide one nonempty uppercase E/P/R sequence per CSV row in the `sequence` column, or pass an iterable of strings to the API. E and R encode positive and negative increments of an even coordinate. If starting from a coordinate, define P with a symmetric threshold and keep sampling and trajectory boundaries explicit. The tool counts windows only within trajectories and weights windows equally. An unavailable contrast is `None` in Python or `null` in JSON. Values are descriptive, with no threshold test, assumption of stationarity, or estimate of uncertainty. The output includes eligible window counts, the raw pause endpoint count, and `q3` for checking Eq. (4). Use the `physical_reverse` helper to reverse the sequence and exchange E and R. Read the assumptions below before interpreting the estimates from real data.

Run the API and CLI tests after installation with `python -m unittest discover -s tests -v`. The installed analysis tools use only the Python standard library.

## Compare modulations across experimental conditions

The v1.1 command takes regularly sampled positions, one sample per row. Use `condition,unit,track,sample,position` as the CSV header. The independent experimental unit might be an animal or independent preparation. Reuse its ID across all nested tracks, give each contiguous track a distinct ID within the unit, and split at missing samples. Sample indices must be consecutive within each track. All tracks must have the same known base sampling interval and a physically even coordinate.

```sh
increment-state-cycles-compare examples/synthetic_modulation.csv \
  --reference control --comparison treated \
  --pause-thresholds 0 0.5 --strides 1 2 \
  --sampling-interval 0.25 --seed 42
```

The Python equivalents are `Track`, `symbolise` and `compare_conditions` from `increment_state_cycles.modulation`. For each grid point, positions are subsampled every *stride* samples from the first point in each track. The software then classifies the displacement as P if its absolute value is at most the pause threshold, in coordinate units. The threshold is a displacement threshold, not a speed threshold. The effective time interval is the stride times the base interval, in whatever time unit the caller uses. Sensitivity is to the specified settings and the first-sample origin. The tool does not average over alternate sampling origins.

Within each unit, eligible windows are pooled across its tracks without crossing a track boundary. Each eligible unit contributes equally to the condition mean. The effect is comparison minus reference. Independent designs resample units within each condition. Use `--design paired` when the same units were measured under both conditions. The software then requires matching input IDs and resamples within-unit differences from pairs with usable data for the endpoint. The output lists the eligible IDs at each grid point, since changing the sampling interval can change the units included. If either condition has no eligible units, the difference is unavailable. With fewer than two eligible units per arm or matched pairs, the interval is unavailable.

Intervals are seeded, pointwise percentile bootstrap intervals over independent units or independent matched pairs. They do not cover the entire sensitivity grid jointly. With few units, bounded or discrete estimates can produce unstable or degenerate intervals. The intervals quantify between-unit uncertainty for the chosen window-pooling and sampling protocol, and do not account for classification error, within-unit measurement error, selection of settings, or confounding. A shift across the grid can result from the sampling rule or from changes in which units are eligible. Report the chosen settings and the full grid rather than selecting a point after examining its interval.

Run `python examples/validate_modulation.py` to reproduce the synthetic benchmark for a known null and a known positive difference in q1.

Install the numerical and figure dependencies described below for these commands. The figure command writes the five manuscript PDFs and SVGs to a new directory. ## Computational environment

The files were prepared and tested in Python 3.14.7, NumPy 2.3.5, SciPy 1.16.3, pandas 2.3.3, SymPy 1.14.0 and R 4.5.2. The R figures use ggplot2 4.0.2, cowplot 1.2.0, svglite 2.2.2, ragg 1.5.0 and jsonlite 2.0.0. Cairo and an installed, appropriately licensed Arial font are required to reproduce the vector typography. Numeric results are portable within usual floating-point tolerance; vector files can differ bytewise across R, Cairo, font, and operating-system versions. These requirements describe the tested current environment, not a guarantee of bitwise reproduction on all platforms.

In a virtual environment install Python dependencies with `python -m pip install -r requirements.txt`. In R install `ggplot2`, `cowplot`, `svglite`, `ragg`, and `jsonlite`. Scripts use paths relative to their own location. Run from a writable copy: several generation scripts overwrite their saved tables and figure files. Use a single CPU thread for the simulation: `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1`.

`DATA_DICTIONARY.md` maps every saved table and its columns to their scientific role.

## Verify published numerical results

From this directory first run `python3 verify_integrity.py` to compare every file listed in `SHA256SUMS` with its recorded digest, including all tables used by the figures. This checks file identity, not mathematical correctness. Python optimization (`python -O` or `PYTHONOPTIMIZE`) disables assertions, so scripts using assertions explicitly reject optimized execution. Then run `python3 run_checks.py`. This reads the saved data and checks selected exact pair examples, reconstruction of simulation summaries, the classification channel, and the finite physical model; it does not independently recompute every exact curve. It does not rerun large Monte Carlo jobs. For the symbolic recovery and asymmetric-error studies, the calibration trajectories themselves are not saved: these checks reconstruct exceedance rates conditional on the stored cutoffs, whereas full regeneration recalculates the cutoffs from the recorded random streams. `python3 test_checks.py` runs negative controls on temporary copies to ensure missing outputs, empty summaries, a corrupted pair matrix and a changed figure-input table are rejected. `published_figures/Figure_1.pdf` through `Figure_5.pdf` are the exact vector PDFs included in the manuscript proof; their SHA-256 digests are recorded in `SHA256SUMS`.

```sh

python3 recuperacao_fisica_20261118/estudo_fisico.py
```

The independent-study counts and lengths can make these jobs substantially more expensive than `run_checks.py`. Run one numerical job at a time. `python3 verify_regeneration.py` copies the package into a temporary directory, reruns the numerical generators and removes each expected output before rerunning its producer and compares the resulting CSV and rotor JSON files to the saved files within tolerance; it may take longer than the read-only checks. Each generator has a 300-second limit; on slower machines, set the positive integer `EPJE_JOB_TIMEOUT_SECONDS` to an appropriate finite limit. Fixed root seeds are 20261117 (finite symbolic recovery), 20261118 (asymmetric error), 20261119 (synthetic calibration), and 2026111803 (physical-rotor recovery). Streams and parameters are specified by the scripts; the rotor uses 600 calibration studies and 600 independently tested studies per model per length, with 24 trajectories per study. Lengths are nested prefixes, not independent replications. Channel-calibration results use 200 studies per condition with 200 block-bootstrap replicates. The supplied `studies.csv`, trajectory tables and summaries are outputs of these runs, not independent biological measurements.

## Scientific assumptions and limits

- E and R label the signs of increments of an even coordinate; P is unchanged by time reversal and E/R are exchanged. The stationary pair classification assumes matched consecutive pair marginals. Finite tracks have the boundary term in the manuscript.
- The cycle/reset and replacement channels are prescribed finite-state models; the data are synthetic. A model-specific null, finite trajectory lengths, and overlapping windows cannot establish an experimental false-positive rate or microscopic entropy production.
- Asymmetric classification can produce a nonzero observed contrast for a reversible latent control. Inverse-channel calculations assume an invertible, stable, time-independent classification channel applied independently at the symbol positions and independently paired reference labels.
- The continuous-time rotor has a two-level marker and a constructed matching point; its three-position and increment-pair laws match a chosen equilibrium comparator, not all equilibrium processes. No parameter was fitted to a cell.
